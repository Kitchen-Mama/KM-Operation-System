- `_spWorkspacePlanRecord` now retains `shipFrom`, `sourceWarehouseId`, the existing 40_ `sourceWarehouse` reference, `shipFromType`, and `submittedAt`. The reference ID also supplies a missing sourceWarehouseId. `_spSubmittedDate_` uses submittedAt/raw.submitted_at, falling back to createdAt/raw.created_at for drafts and legacy records. Zoned timestamps convert to Asia/Taipei; Sheets wall-clock text is treated as Taipei, not the browser timezone. Invalid or absent dates show `--`.
- `_spResolveShipFrom_` resolves the exact matching sourceWarehouse `{id,code,name}` reference on cold visits without a broad-master read. Explicit projected duplicates still display the ID; mismatched references are ignored. Legacy records may resolve a unique cached master row, or display their existing ship_from snapshot when no canonical ID exists. No names are invented.
- `_spWorkspaceLineRecord` retains optional `liveSiteMetrics` separately from immutable raw snapshots. `_spLiveSiteMetrics_` requires READY state, exact nonblank company/country/marketplace/SKU (line marketplace takes priority), and finite nonnegative measured values. Fresh readings display without frontend sales/Days-of-Supply calculations. Measured zero remains zero; null, missing, invalid, pending, refused, failed, or cross-site readings never become zero. Without a usable fresh reading the existing snapshot display remains.
- Parent identified the missing-data root: 16_ environment gate emits SITE_SOURCE_SCOPE_UNDECIDED in Production, and this page returned unavailable before reading any other source. A fresh exact-site reading can recover that obsolete warning without changing raw. All other SOURCE_COMPANY/NOT_CONFIRMED/marketplace guards remain enforced, including mixed warnings.
- Shared `KM.display.shippingMethod`, `lastMileDelivery`, and `shippingService` are consumed. Hilbert confirmed and implemented those APIs in DB API. shippingService accepts snake-case service fields, prefers a real supplied shipping_method_label, otherwise displays method + last mile. Labels are not persisted.
- Domestic/manual controls have one `.sp-svc-service[data-field="shipping_service"]` picker, backed only by exact declared carrier.services tuples with services_known=true and vocabulary membership. Hidden `.sp-svc-method`/`.sp-svc-lastmile` retain canonical values. Carrier changes clear the choice. Save validates the tuple again and uses the existing selectShippingPlanRateCardWithCustoms writer, expected token, customs gate, and service readback checks.
- Review quote choices use the same service-label helper. No frontend tier filtering, cheapest selection, first-carrier default, or method-only fallback was added. A persisted carrier + exact method/last-mile pair can restore one unique candidate; multiple candidates remain blank. Blank selections no longer coerce to numeric option zero. Unsaved quote restoration requires unique identity matches.
