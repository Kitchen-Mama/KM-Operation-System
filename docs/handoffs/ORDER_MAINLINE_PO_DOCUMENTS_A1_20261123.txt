1. Delivered

PO document prices now consume purchase_order_lines.unit_cost, amounts consume
persisted line_amount (including the writer's rounding), and the working ready
date consumes expected_completion_date. The document model exposes both canonical
names and legacy unit_price/expected_ready_date aliases for saved mappings.

Canonical blank or invalid money remains unknown, not a fabricated zero or a
stale legacy price. A missing amount makes the total unknown instead of printing
a partial total. Required template values block before reserving a document or
creating a folder/file. Actual zero values remain zero. Supplier expected and
confirmed dates are NOT populated from working completion dates.

Canonical cost, amount and completion-date edits now change the source checksum.
An existing READY document of a Draft PO is reused only when its recorded source
checksum and document date match. Otherwise its registry row is superseded and
a replacement is generated; original Drive files are retained, not deleted.
Legacy Draft documents without a verifiable checksum are regenerated as well.

Send PO rechecks the source and READY registry row after reacquiring the issue
lock, including its reuse path. A changed source or invalidated document blocks
issue and leaves the PO Draft. Existing already-issued document history is not
silently rewritten by this Draft-only correction.

13_ changed ONLY the Send PO completed-document reuse guard. Request approval,
conversion compensation and receipt rules are not modified by this checkpoint.
39_ owns the model mapping, checksum reuse and source verification changes.
No frontend, router, health manifest, DB schema or generated 90_ bundle change.
