Scope: one narrow Shipment import change. Order mainline remains ON HOLD at the owner's request.
No live business DB writes, no Apps Script deployment, no credentials/config adapters read or copied.

Behavior
- Header source label is now 出貨倉, in Add New and Update templates.
- Keep old 出貨工廠倉 / 出貨工廠倉 source_warehouse_id labels as parser aliases; stable key remains source_warehouse_id.
- Existing active factory source eligibility is preserved, including shared factories owned by another company.
- Also offer active 3PL overseas warehouses whose company exactly equals the selected import company.
- With no company selected, do not offer overseas sources. Never infer a missing company.
- Reject pasted/typed cross-company, inactive, ownerless, FBA, RETURN, unknown-type and unknown overseas sources.
- Unknown/duplicate warehouse ids and source=destination remain refusals.
- Carrier services must still support the source/destination lane. A dropdown choice does not waive that check.
- Update source stays read-only: this change cannot move an existing shipment to another source.
- Destination eligibility, COUNTED vs DISPLAY_ONLY, tracking/receipt logic and import idempotency are unchanged.
- This imports goods ALREADY in transit. No second source-stock deduction, reservation or PO allocation is made.
- Optional existing route-position behavior is unchanged; this patch does not add or enable it.
