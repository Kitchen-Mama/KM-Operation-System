## Architecture
`shipment_id → docReadSnapshot_ (frozen R2B) → docRenderShippingDetail_/PL (R3A model) → dtResolveTemplate_ (R3B) → dtMapPlaceholders_ (R3B) → dfoGenerateFile_ (R3C: copy template asset, fill tokens, export PDF) → generated_documents file metadata → download_url`. The renderer receives the resolved template + mapped model; it NEVER reads a live master, resolves a template, maps placeholders, or recomputes a fact. Raw Drive/Sheets calls are isolated in `dfoDefaultIo_`; the fill/expand logic is pure (unit-tested with a fake io).
